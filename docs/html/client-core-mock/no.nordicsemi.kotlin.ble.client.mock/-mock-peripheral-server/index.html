MockPeripheralServer

class MockPeripheralServer : LocalServerImpl<String>

A GATT server hosted by a mock peripheral, PeripheralSpec.

It is a no.nordicsemi.kotlin.ble.server.LocalServer, the same one that apps use to implement the peripheral role, running on top of a simulated GATT server. Every connectable PeripheralSpec hosts one, also when its services are defined with the DSL of the builder (see PeripheralSpec.server). It answers the requests of the mock clients: read and write requests, long and reliable writes, and subscriptions are handled by the handlers set with onRead and onWrite of the local characteristics and descriptors, and by their values, and notifications and indications are sent with update().

The requests of the clients go through the same simulation as the requests to peripherals using other peripherals: they take as much time as the transfer of the value, using the connection interval, the MTU and the PHY of the connection, and are subject to the same checks of permissions, bonding and the validity of cached services.

Sample code:

val server = MockPeripheralServer(scope = backgroundScope)
val services = server.setup {
    GenericAccessService()
    GenericAttributeService()
    Service(BLINKY_SERVICE_UUID) {
        Characteristic(
            uuid = LED_UUID,
            properties = CharacteristicProperty.READ and CharacteristicProperty.WRITE,
            permissions = Permission.READ and Permission.WRITE,
        )
        Characteristic(
            uuid = BUTTON_UUID,
            properties = CharacteristicProperty.READ and CharacteristicProperty.NOTIFY,
            permission = Permission.READ,
        )
    }
}
val led = services.single { it.uuid == BLINKY_SERVICE_UUID }.characteristics.first { it.uuid == LED_UUID }
val button = services.single { it.uuid == BLINKY_SERVICE_UUID }.characteristics.first { it.uuid == BUTTON_UUID }
led.onWrite { if (value.size == 1) WriteResponse.Success else WriteResponse.Failure(OperationStatus.InvalidAttributeLength) }
led.writes.onEach { println("LED: ${it.value.first()}") }.launchIn(backgroundScope)

val peripheral = PeripheralSpec.simulatePeripheral(identifier = "01:02:03:04:05:06") {
    advertising { CompleteLocalName("Blinky") }
    connectable(name = "Blinky", server = server)
}
// ... later, when a client has subscribed to the button:
button.update(byteArrayOf(1))

Services

Define the services, like on a real device, using setup, before a client discovers them (the services are discovered from the server when the client asks for them). The services of the Generic Access and Generic Attribute, if needed, are declared with GenericAccessService and GenericAttributeService. As with PeripheralSpec.Builder.connectable using PeripheralSpecEventHandler, their Device Name, Appearance and Peripheral Preferred Connection Parameters characteristics return the values from the PeripheralSpec, and Service Changed is handled automatically. Use PeripheralSpec.simulateServiceChange to replace the services of a peripheral that is in use: calling setup again does not notify the clients.

Threading and time

Requests are processed by the event loop of the manager, which runs in the given scope. The simulated transfers use the dispatcher and the clock of the mock central manager, so in tests using runTest, the scope should use the same test scheduler, for example backgroundScope. Handlers may suspend, for example to simulate a slow peripheral, using virtual time.

Limitations

  • One server can be used by one PeripheralSpec only.

  • The only client is client, the phone. It is the same for all the clients of the peripheral.

  • PeripheralSpec.simulateValueUpdate sends a notification to the clients, but it bypasses the server. Use update() of the local characteristic instead.

Simulating faults

The server handles Prepare Write, Execute Write and Client Characteristic Configuration requests itself. To simulate a fault at the level of ATT requests, set an interceptor.

scope

The scope of the event loop of the manager, which also runs the handlers.
